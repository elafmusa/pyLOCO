## Portable starter policy

The supported public starter is `mdt_smoke/build_modern_ebs_package.py`, not a
partially populated `.pyloco.json` file. The builder takes the operator's
approved lattice, measurement session and Correct mapping, verifies their
actual identities and fingerprints, and then writes the restricted project
with QD3J/27, QF4J/36 and QD5B/51 plus two short LM iterations. This avoids a
template that appears runnable while lacking authoritative measurement order or
mapping evidence.

There is likewise no generic Measure device-selection file. Such a file stores
exact BPM and H/V corrector identities for one connected inventory. Simone
should create or load one only after connecting to the approved simulator and
reviewing the selected identities. It is not consumed directly by FIT.

## What each file controls

- A Measure device-selection configuration preserves BPM/H/V checked
  identities, order, methods, filters and exclusions for one Measure workflow.
  FIT does not consume it directly.
- The HDF5/session files carry the ordered measured identities and arrays.
- FIT's measurement mapping binds those HDF5 identities to exact AT ordinals
  and is checksum/inventory bound.
- The FIT project supplies lattice, machine selections, exclusions, fitting
  groups, weights, optimizer options and recipe.
- Correct's mapping separately binds fitted lattice name+ordinal identities to
  exact pyAML B2L/A2L controls. It cannot be replaced by the Measure/FIT mapping.

## Package layout for approved transfer

Use the generated layout intact:

```text
mdt_package/
  configs/
    EBS_pyaml_MDT_smoke.pyloco.json
    betamodel_conf_pyaml_test.local.yaml
  lattice/betamodel.mat
  measurements/
    measurement-session.pyloco-session.json
    <three HDF5 files>
  mappings/
    EBS_measurement_devices.validated.local.json
    EBS_three_quadrupoles.correct.validated.json
  results/
  VALIDATION.json
```

Project paths are relative and relocation was GUI-tested. `VALIDATION.json`
contains an absolute build-machine project path and must be sanitized or
regenerated after transfer if it is to be shared.

Do not publish machine credentials, production endpoints, private YAML,
unauthorized lattice/measurement data, generated results, transaction journals,
or personal absolute paths. The current October 18 HDF5 metadata and project
also record personal paths and a live/write-capable acquisition context, so
they are local/approved-transfer artifacts, not public fixtures.
